## 1. Введение и философия языка

### 1.1 Главная идея

Язык **Runvoid** возник из простого и насущного вопроса: **Почему программист должен выбирать между простым английским синтаксисом и бешеной скоростью машинного кода?**

Обычно в мире программирования есть два полюса:
- Скриптовые языки вроде **Python** или **Ruby** понятны даже школьнику, но выполняются через медленные виртуальные машины или интерпретаторы, расходуют сотни мегабайт оперативной памяти и требуют тяжелых окружений.
- Системные языки вроде **C**, **C++** или **Rust** дают максимальную скорость процессора и крошечный размер программ, но перегружены сложными знаками препинания, заголовочными файлами, указателями и сложными правилами компилятора.

**Runvoid соединяет лучшее из обоих миров:**
1. **Читается как обычный английский текст:** Команды понятны без расшифровки: `say "Привет"`, `remember score = 100`, `repeat 5 times`, `for every item in backpack`, `if file "save.dat" exists`.
2. **Чистая нативная компиляция:** Runvoid — это **не** интерпретатор. Компилятор, написанный на **Rust**, напрямую превращает код в **чистый ассемблер x86_64 NASM**, линкуя его в автономный бинарный исполняемый файл Linux ELF размером от **15 килобайт** — без Node.js, Python или тяжелых рантаймов.
3. **Бесшовный переход от новичка к хардкорному системщику:** Начинающий может писать понятные сценарии, не зная, что такое указатель или стек. А когда проекту нужна максимальная производительность, три короткие директивы превращают Runvoid в строгий системный язык с ручным управлением памятью, C FFI и встроенным ассемблером.

### 1.2 Двухуровневая архитектура (Для новичков и Профи)

| Возможность | Базовый режим (По умолчанию) | Системный Pro-режим (`add Advanced`) |
|---|---|---|
| **Стиль синтаксиса** | Разговорный, понятный английский | Строгий, лаконичный системный стиль |
| **Система типов** | Автоматический вывод типов | Строгая статическая типизация (`: Int`, `: String`, `: Ptr`) |

### 1.3 Как устроен компилятор (Конвейер сборки)

Когда вы запускаете `runvoid run` или `runvoid build`, программа проходит через четкие этапы:

1. **Лексер (Lexer):** Читает исходный текст `.rv` и разбивает его на смысловые токены (слова, числа, строки с интерполяцией `{...}`).
2. **Парсер (Parser):** Превращает цепочку токенов в иерархическое дерево — AST (абстрактное синтаксическое дерево), попутно рекурсивно подключая импортированные файлы (`use "file.rv"`).
3. **Проверка типов (TypeChecker):** Проверяет корректность типов, наличие функций и модулей, а также соблюдение правил директив.
4. **Оптимизатор (Optimizer):** Сворачивает математические константы на этапе сборки (Constant Folding) и вычищает недостижимый «мертвый код» (Dead Code Elimination).
5. **Генератор кода (CodeGen):** Преобразует узлы AST в оптимизированный ассемблерный код x86_64 для ассемблера NASM.
6. **Ассемблер (NASM):** Транслирует ассемблер в объектный файл ELF64.
7. **Компоновщик (Linker):** Линкует объектный файл через GCC (или напрямую через `ld -s` в freestanding режиме) в финальный независимый исполняемый файл.

## 2. Быстрый старт: Мои первые 5 минут

### Шаг 1: Первая программа
Создайте текстовый файл `hello.rv`:
```runvoid
say "Привет, прекрасный мир Runvoid!"
```
Запустите его одной командой в терминале:
```bash
runvoid run hello.rv
```
> **Результат в терминале:**
> `Привет, прекрасный мир Runvoid!`

---

### Шаг 2: Переменные («Запомни»)
В Runvoid вместо непонятных сокращений вроде `var` или `let` используется живое слово `remember` («запомни»):
```runvoid
remember player = "Алекс"
remember score = 100

say "Игрок: {player}, Очки: {score}"
```
Если нужно изменить значение существующей переменной, просто присвойте новое значение:
```runvoid
score = score + 50
say "Новый счет: {score}"
```

---

### Шаг 3: Ввод пользователя («Спроси»)
Задавайте вопросы с помощью команды `ask`:
```runvoid
remember name = ask "Как зовут твоего героя? "
say "Добро пожаловать в игру, {name}!"
```

---

### Шаг 4: Принятие решений (ветвление)
Ветвление строится на естественных фразах: `if` («если»), `otherwise if` («иначе если») и `otherwise` («иначе»):
```runvoid
remember gold = 75

if gold >= 100 {
    say "Ты можешь купить легендарный меч!"
} otherwise if gold >= 50 {
    say "Золота хватает на прочный щит."
} otherwise {
    say "Нужно накопить еще золота, искатель приключений."
}
```

---

### Шаг 5: Повторение действий (циклы)
Повторяйте действия фиксированное число раз или пока истинно условие:
```runvoid
# Повторить ровно 3 раза:
repeat 3 times {
    say "Ура!"
}

# Повторить с переменной-счетчиком:
repeat 5 as step {
    say "Шаг номер: {step}"
}

# Цикл пока условие верно:
remember energy = 3
while energy > 0 {
    say "Бежим! Осталось энергии: {energy}"
    energy = energy - 1
}
```

---

### Шаг 6: Функции («Действие» и «Верни»)
Функции объявляются словом `action` («действие»), а результат возвращается через `give` («верни / дай»):
```runvoid
action calculate_damage(attack, defense) {
    give attack * 2 - defense
}

remember dmg = calculate_damage(20, 5)
say "Нанесенный урон: {dmg}"
```

## 3. Установка и настройка окружения

Runvoid собирает бинарники для архитектуры **Linux x86_64**. Убедитесь, что установлены необходимые системные инструменты:

```bash
# Для Arch Linux:
sudo pacman -S rust cargo nasm gcc libx11

# Для Ubuntu / Debian / Linux Mint:
sudo apt update && sudo apt install -y rustc cargo nasm gcc libx11-dev

# Для Fedora:
sudo dnf install -y rust cargo nasm gcc libX11-devel
```

### Сборка компилятора из исходников:
```bash
git clone https://github.com/runvoid/runvoid.git
cd runvoid
cargo build --release
sudo cp target/release/runvoid /usr/local/bin/
```
Проверьте установку:
```bash
runvoid --version
# runvoid 0.2.0
```

## 4. Интерфейс командной строки (CLI)

### 4.1 Мгновенный запуск скриптов (`run`)
Компилирует файл во временную память и сразу запускает — идеальный режим для быстрой разработки и скриптов:
```bash
runvoid run script.rv
```

### 4.2 Компиляция в автономный бинарник (`build`)
Создает оптимизированный автономный исполняемый файл:
```bash
runvoid build script.rv -o my_app
./my_app
```
С флагом `--verbose` вы увидите подробный отчет о фазах компиляции:
```bash
runvoid build script.rv -o my_app --verbose
```

### 4.3 Просмотр ассемблера (`emit-asm`)
Выводит сгенерированный ассемблерный код NASM прямо на экран:
```bash
runvoid emit-asm script.rv
```

### 4.4 Автоформатирование кода (`fmt`)
Встроенный форматер аккуратно расставляет отступы, пробелы и фигурные скобки:
```bash
runvoid fmt script.rv       # Показать отформатированный код в терминале
runvoid fmt -w script.rv    # Перезаписать файл красивым кодом на месте
```

### 4.5 Создание шаблонов проектов (`new`)
Мгновенно создает рабочий каркас проекта для новичков:
```bash
runvoid new game flappy.rv   # Шаблон 2D игры с графическим холстом
runvoid new gui panel.rv     # Шаблон оконного настольного интерфейса
runvoid new script app.rv    # Шаблон простого разговорного скрипта
```

### 4.6 Шпаргалка в терминале (`cheat`)
Показывает удобную цветную шпаргалку по всем возможностям языка прямо в консоли:
```bash
runvoid cheat
```

## 5. Руководство для новичков (Базовый синтаксис)

### 5.1 Вывод текста и цвета (`say`, `say same`, ANSI)

- `say` выводит текст или число и переводит строку на новую.
- `say same` выводит текст, **не** переводя строку (оставаясь на той же строке).
- Цветные слова раскрашивают терминал без странных спецсимволов:

```runvoid
say "Обычный белый текст"
say green "Успех: операция завершена!"
say red "Ошибка: файл не найден."
say yellow "Предупреждение: память почти заполнена."
say blue "Информация: подключение к серверу..."
say cyan "Уведомление: проверьте почту."
say magenta "Бонус: получен новый уровень!"

# Печать в одну строку:
say same "Выполняется загрузка: "
say same green "[ГОТОВО] "
say same "(100%)\n"
```

---

### 5.2 Переменные и вставка значений (`remember`, `{...}`)

Переменные создаются через ключевое слово `remember`. В базовом режиме тип указывать не нужно — компилятор всё сделает сам:
```runvoid
remember count = 10
remember greeting = "Привет"
remember is_ready = true
```

#### Вставка значений в строки (интерполяция):
Внутри двойных кавычек фигурные скобки `{...}` вычисляют любое выражение:
```runvoid
say "{greeting}! У тебя {count} очков, а удвоенное значение: {count * 2}."
```

---

### 5.3 Понятная математика, сравнения и логика

Runvoid поддерживает как привычные математические знаки, так и понятные слова:

| Операция | Слово | Символ | Пример |
|---|---|---|---|
| Сложение | `+` | `+` | `a + b` |
| Вычитание | `-` | `-` | `a - b` |
| Умножение | `*` | `*` | `a * b` |
| Деление | `/` | `/` | `a / b` |
| Остаток от деления | `%` | `%` | `a % b` |
| Равно | `is` | `==` | `if score is 100` |
| Не равно | `is not` | `!=` | `if health is not 0` |
| Меньше / Больше | `<` / `>` | `<` / `>` | `if age < 18` |
| Логическое И | `and` | `and` | `if a and b` |
| Логическое ИЛИ | `or` | `or` | `if a or b` |
| Логическое НЕ | `not` | `not` | `if not finished` |

### 5.4 Управление ходом программы (`if`, `otherwise`, `while`, `repeat`)

#### Ветвление:
```runvoid
remember temperature = 22

if temperature > 30 {
    say "На улице жара!"
} otherwise if temperature > 15 {
    say "Отличная комфортная погода."
} otherwise {
    say "Надень теплую куртку!"
}
```

#### Циклы:
```runvoid
# Цикл repeat со счетчиком шагов (начиная с 0):
repeat 3 as i {
    say "Шаг: {i}"
}

# Цикл while:
remember k = 1
while k <= 3 {
    say "Счетчик: {k}"
    k = k + 1
}

# Прерывание циклов:
repeat 10 as step {
    if step is 2 {
        skip    # Пропустить эту итерацию (continue)
    }
    if step is 5 {
        stop    # Немедленно выйти из цикла (break)
    }
    say step
}
```

### 5.5 Разговорные списки слов

Списки в Runvoid работают так же просто, как список покупок в блокноте:


## 6. Управление памятью и Сборщик Мусора (GC)

### 6.1 Автоматический сборщик мусора Mark-and-Sweep
В базовом режиме работы строки и списки Runvoid управляются встроенным компактным сборщиком мусора типа **Mark-and-Sweep**:
- Он сам освобождает память, когда объекты больше не используются.
- Новичкам не нужно думать об утечках памяти или `free()`.
- Безопасность памяти гарантирована.

### 6.2 Отключение сборщика мусора (`remove garbageC`)
Если вы пишете требовательную программу, где недопустимы паузы на сборку мусора, просто добавьте директиву в начало файла:
```runvoid
remove garbageC
```
Сборщик мусора будет полностью отключен, а аллокации пойдут напрямую через быстрый прямой аллокатор кучи.

## 7. Профессиональный системный режим (`add Advanced`)

Когда вам требуется бескомпромиссная производительность, прямой доступ к регистрам процессора, аппаратные потоки и микроскопический размер бинарников — Runvoid превращается в мощный системный инструмент.

### 7.1 Директивы и активация
Для включения режима Pro объявите три директивы в самом начале исходного файла:
```runvoid
remove garbageC
remove Basic
add Advanced
```
Что это делает:
1. `remove garbageC`: Отключает рантайм сборщика мусора.
2. `remove Basic`: Отключает нестрогий вывод типов и требует явных типов.
3. `add Advanced`: Включает доступ к системным модулям, указателям, inline-ассемблеру и агрессивным оптимизациям компилятора.

---

### 7.2 Строгая статическая типизация (`remove Basic`)
В режиме Pro каждая переменная, аргумент и возвращаемое значение функции обязаны иметь явный тип:
```runvoid
remember count: Int = 42
remember title: String = "Ядро системы"
remember ready: Bool = true

action multiply(x: Int, y: Int): Int {
    give x * y
}
```
Поддерживаемые типы:
- `Int`: 64-битное целое со знаком.
- `String`: Строка с 8-байтным префиксом длины и нуль-терминатором.
- `Bool`: Логический тип (0 или 1).
- `Ptr`: 64-битный сырой указатель в память.
- `Void`: Пустой тип (для процедур).
- Пользовательские структуры (например, `Point`, `Node`).

---

### 7.3 Модульная стандартная библиотека (`use ior`, `math` и др.)
В Pro-режиме стандартная библиотека разделена на независимые модули. В бинарник попадает только то, что вы явно импортировали:

```runvoid

use fs        # Прямая работа с файлами: read, write, copy, delete
use net       # Сетевые сокеты TCP: tcp_listen, tcp_accept, tcp_connect, tcp_send, tcp_recv, tcp_close
use thread    # Нативные потоки ОС: thread { ... } (линкует -lpthread)
```

Пример программы с математикой:
```runvoid

add Advanced

remember root: Int = sqrt(144)
say root   # 12
```

### 7.5 Bare-Metal режим без ОС и без libc (`add Freestanding`)

Для разработки ядер ОС, загрузчиков, драйверов и микроконтейнеров, где **недопустимы даже libc и библиотеки C**:

```runvoid

remove Basic
remove Linux
add Advanced
add Freestanding

# Компилятор генерирует точку входа 'global _start' вместо main.
# Вызываем Linux syscall напрямую:
asm {
    mov rax, 60    ; Системный вызов sys_exit
    xor rdi, rdi   ; Код возврата 0
    syscall
}
```
В режиме `Freestanding`:
- Бинарник линкуется напрямую через `ld -s` (без GCC и libc).
- Итоговый файл содержит **только чистый машинный код** без единой внешней зависимости.

### 7.11 Нативная многопоточность и аппаратные атомики

Создавайте нативные потоки Linux POSIX и выполняйте атомарные операции на уровне инструкций процессора:

```runvoid
remove garbageC
remove Basic
add Advanced
use ior
use thread

remember shared_counter: Int = 0

# Запуск фонового потока:
thread {
    atomic add shared_counter, 10
}

wait 1
say shared_counter    # 10
```
Инструкция `atomic add` транслируется в аппаратную процессорную инструкцию `lock add [reg], rax`, гарантируя отсутствие гонок данных (data race) между ядрами процессора.

---

### 7.12 Оптимизации компилятора

При включении `add Advanced` компилятор Runvoid применяет глубокие оптимизации:
1. **Сворачивание констант (Constant Folding):** Выражения вроде `10 * 10 + 50` вычисляются на этапе компиляции и записываются сразу как число `150`.
2. **Удаление мертвого кода (DCE):** Инструкции после `give`, `stop` или `skip` отсекаются еще до генерации ассемблера.
3. **Peephole-оптимизации:** Замена медленных инструкций ассемблера на быстрые аналоги (`xor eax, eax`, `inc/dec`).
4. **LTO и Stripping:** Сборка с флагами `nasm -O3` и `gcc -O3 -flto -s -Wl,--gc-sections`, обеспечивающая рекордную скорость и минимальный размер бинарника.

## 9. Частые ошибки и вопросы (FAQ)

### Вопрос 1: Почему в терминал напечаталось `{my_var}` буквально, а не значение?
**Ответ:** Интерполяция строк работает только внутри двойных кавычек:
```runvoid
# Правильно:
say "Твой результат: {my_var}"

# Неправильно:
say my_var    # Если нужно напечатать просто переменную, пишите: say my_var
```

---

### Вопрос 2: Почему компилятор выдает ошибку при указании `add Advanced`?
**Ответ:** Чтобы случайно не сломать новичковый код, режим Pro требует явного подтверждения отказа от высокоуровневых механизмов:
```runvoid
# Обязательно укажите все три директивы:
remove garbageC
remove Basic
add Advanced
```

---

### Вопрос 3: Почему в режиме Pro не работает команда `say`?
**Ответ:** В режиме Pro в бинарник не линкуется ничего лишнего. Чтобы использовать ввод-вывод, подключите модуль `ior`:
```runvoid
use ior
```

---

### Вопрос 4: Как сделать микроскопический бинарник без libc вообще?
**Ответ:** Используйте директивы режима Freestanding:
```runvoid
remove garbageC
remove Basic
remove Linux
add Advanced
add Freestanding

asm {
    mov rax, 60
    xor rdi, rdi
    syscall
}
```
Runvoid соберет его напрямую линковщиком GNU `ld -s` без единого байта внешних библиотек.

---

### Вопрос 5: Как подключить библиотеку Raylib или SQLite?
**Ответ:** С помощью команды `use lib`:
```runvoid
use lib "raylib"
use lib "sqlite3"
```
Убедитесь, что в системе установлен соответствующий пакет (`libraylib.so` или `libsqlite3.so`).
